# Changelog
All notable changes to this project will be documented in this file.  
The format follows the principles of Keep a Changelog.

---

## [2.2.0] — 2025-12-21
### Added
- Полная исходная документация проекта на базе Doxygen.
- Архитектурные страницы подсистем (UPS, SNMP, GUI, utils).
- README оформлен как отдельная Doxygen-страница и синхронизирован с архитектурой проекта.
- Инфраструктура генерации HTML- и RTF-документации.

### Changed
- Уточнён и зафиксирован публичный API проекта.

### Quality
- Проект доведён до документированного, воспроизводимого и сопровождаемого состояния.

---

## [2.1.2] — 2025-12-20
### Added
- Добавлены инструменты статического анализа кода:
  - `clang-tidy` с режимами `light / medium / strict`
  - `cppcheck` с настроенным профилем проекта.

### Fixed
- Устранены неявные преобразования типов (`long -> int`).
- Исправлена обработка ожидаемых исключений (`std::stoi`).
- Удалены неиспользуемые переменные и ложные контракты.
- Заменены небезопасные C-style cast на `reinterpret_cast`.

### Quality
- Повышено общее качество кода за счёт внедрения статического анализа.
- Снижено количество потенциальных дефектов, выявляемых на этапе компиляции и анализа.

---

## [2.1.1] — 2025-12-19
### Changed
- Доведено unit-покрытие SNMP компонентов до 100%
- Исключены из покрытия недостижимые defensive-ветки

---

### [2.1.0] — 2025-12-19
### Added
- Полный набор unit-тестов для `UpsEmulator`, включая:
  - жизненный цикл (`start / stop`)
  - ограничения состояний
  - негативные сценарии конфигураций
  - сеттеры параметров UPS.
- Негативные сценарии выбора модели UPS.

### Changed
- Упрощена и стабилизирована логика `UpsEmulator::start()` и `fillDefaults()`.
- Улучшена диагностика и обработка ошибок при запуске эмулятора.

### Fixed
- Устранены потенциальные зависания при остановке `UpsEmulator`.
- Повышена надёжность жизненного цикла SNMP-агента.

### Quality
- Покрытие `UpsEmulator` unit-тестами доведено до 100%.

---

### [2.0.0] — 2025-12-17
### Added
- Графический интерфейс пользователя (GUI) на базе Qt.
- Возможность выбора модели UPS и управления запуском/остановкой эмулятора через GUI.
- Отображение и изменение параметров UPS в реальном времени из GUI.
- Возможность выбора модели UPS через аргументы командной строки при работе в CLI.

### Changed
- `UpsEmulator` стал центральным фасадом системы и используется как в CLI, так и в GUI.
- Управление жизненным циклом SNMP-агента (`start / stop / isRunning`) унифицировано.
- `UpsDataStore` сделан потокобезопасным.
- Структура unit-тестов приведена в соответствие со структурой исходного кода.
- Переработана сборочная инфраструктура (CMake, layout build/bin/tests).
- Тесты сделаны независимыми от рабочей директории.

### Fixed
- Удалена отладочная печать из `SnmpAgent`.
- Исправлены потенциальные проблемы потокобезопасности при доступе к данным UPS.

---

## [1.0.3] — 2025-12-13
### Changed
- `UpsEmulator` управление жизненным циклом SNMP-агента инкапсулировано внутри `run()`.
- Удалён публичный метод `bind()` из `UpsEmulator`.
- Запуск эмулятора теперь невозможен без выбранной модели.

### Fixed
- Запрещена смена модели при работающем SNMP-агенте.
- Исправлена обработка ошибок при инициализации дефолтных значений UPS.

---

## [1.0.2] — 2025-12-12
### Fixed
- Исправлена логика запуска и остановки SNMP-агента.
- Устранена блокировка при `recvfrom()` за счёт перехода на `poll()`.

### Changed
- Жизненный цикл `SnmpAgent` приведён к явной модели состояний (`bind / run / stop / isRunning`).
- Добавлена защита от повторного вызова `bind()`.

### Added
- Модульные тесты, покрывающие жизненный цикл `SnmpAgent`.

---

## [1.0.1] — 2025-12-11
### Changed
- Проведён рефакторинг архитектуры: создан отдельный класс `UpsEmulator`, который инкапсулирует всю логику работы эмулятора.  
  Функция `main()` теперь выполняет только роль входной точки и не содержит бизнес-логики.

---

## [1.0.0] — 2025-12-10
### Added
- Первая рабочая версия эмулятора ИБП.
- Реализована обработка SNMP-запросов типа GET для протоколов SNMP v1 и SNMP v2c.
- Добавлена поддержка модели APC.  
  (Файл конфигурации содержит секции для APC и INELT, однако в данной версии используется только APC.)
- Реализованы ответы для следующих OID:
  - `modelName`
  - `inputVoltage`
  - `inputFreq`
  - `outputVoltage`
  - `batteryStatus`
  - `chargeRemaining`
  - `batteryTemp`
  - `outputStatus`
