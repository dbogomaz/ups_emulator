# UPS Emulator

Эмулятор SNMP-совместимого ИБП (UPS) с поддержкой SNMP v1/v2c, BER-кодирования, конфигурации моделей через INI-файл и модульной архитектурой. Проект предназначен для разработки и тестирования систем мониторинга без необходимости подключения реального оборудования.

## Возможности

- Обработка SNMP GET-запросов (v1 и v2c).
- Кодирование и декодирование BER/ASN.1.
- Модульная структура для поддержки различных моделей UPS (APC, INELT и др.).
- Загрузка конфигураций моделей из файла `ups_models.ini`.
- Хранилище параметров UPS с типами, значениями и правилами валидации.
- Встроенный эмулятор поведения UPS.
- Управление эмулятором через командную строку (CLI).
- Графический интерфейс пользователя (GUI) на базе Qt.
- Полный набор модульных тестов (GoogleTest).
- Инструменты для анализа покрытия тестами.

## Архитектура проекта

Проект состоит из нескольких логических модулей:

```
src/
  main.cpp                      — точка входа (CLI)
  emulator/                     — логика эмуляции UPS
  snmp/                         — SNMP-агент, кодек, BER-энкодер и логика обработки запросов
  ups/                          — модели UPS, параметры, OID, value-sets
  utils/                        — утилиты (fs_utils, string_utils, ini_section_reader)
gui/
  main.cpp                      — точка входа GUI
  main_window.*                 — графический интерфейс
tests/
  unit/                         — модульные тесты
  data/                         — тестовые INI-файлы
  coverage/                     — инфраструктура анализа покрытия
```

## Сборка проекта

Для сборки используется CMake 3.10+, компилятор с поддержкой стандарта C++11.

### Сборка по умолчанию (включены тесты и покрытие):

```bash
rm -rf build
cmake -B build
cmake --build build
```

Исполняемые файлы `ups_emulator` и `ups_emulator_gui` помещаются в каталог:

`build/bin`

Файл конфигурации `ups_models.ini` копируется в каталог:

`build/bin/config`

Исполняемые файлы тестов и скрипт для проверки покрытия тестами помещаются в каталог:

`build/bin/tests`

### Сборка без тестов и покрытия:

```bash
rm -rf build
cmake -B build -DBUILD_TESTING=OFF -DBUILD_COVERAGE=OFF
cmake --build build
```

## Запуск эмулятора

### Запуск эмулятора (CLI)

SNMP-агент использует привилегированный порт 161, поэтому требуется запуск от имени root:

```bash
sudo ./build/bin/ups_emulator
```
По умолчанию используется первая доступная модель из `ups_models.ini`.

### Выбор модели UPS через аргументы командной строки

```bash
sudo ./build/bin/ups_emulator --model APC
sudo ./build/bin/ups_emulator --model INELT
# Короткая форма
sudo ./build/bin/ups_emulator -m APC
sudo ./build/bin/ups_emulator -m INELT

```
Список доступных моделей берётся из файла конфигурации `ups_models.ini`.

### Запуск эмулятора (GUI)

Для запуска графического интерфейса выполните:

```bash
sudo ./build/bin/ups_emulator_gui
```

GUI позволяет:

- выбрать модель UPS;
- запускать и останавливать SNMP-агент;
- изменять параметры UPS в реальном времени;
- наблюдать текущее состояние эмулятора.

## Проверка работы через SNMP

Пример запроса:

```bash
snmpget -v2c -c public localhost 1.3.6.1.4.1.318.1.1.1.1.1.1.0
```

Для выполнения запросов ко всем поддерживаемым OID можно использовать скрипт:

```bash
./run_snmpget.sh
```

## Тестирование

```bash
ctest --output-on-failure --test-dir build
```

Все исполняемые файлы тестов располагаются в каталоге:

`build/bin/tests`

## Покрытие тестами

Отчёт о покрытии можно получить командой:

```bash
./build/bin/tests/run_coverage.sh
```

Результаты автоматически открываются в браузере.

## Статический анализ кода

В проекте используются инструменты статического анализа для повышения качества и надёжности кода.

### clang-tidy

Для запуска clang-tidy используется скрипт:

```bash
./run_clang_tidy.sh
```
Поддерживаются режимы анализа:

- `light` — минимальный, малошумный анализ (по умолчанию)
- `medium` — расширенный анализ
- `strict` — строгий аудит кода

Пример запуска:

```bash
CLANG_TIDY_MODE=medium ./run_clang_tidy.sh
```

Возможен анализ отдельных файлов:

```bash
./run_clang_tidy.sh src/snmp/snmp_agent.cpp
```

⚠️ На `macOS` требуется предварительная генерация `compile_commands.json` с указанием `CMAKE_OSX_SYSROOT` (подробности см. комментарии в скрипте).

### cppcheck

Для анализа с помощью cppcheck используется скрипт:

```bash
./run_cppcheck.sh
```



## Конфигурация моделей UPS

Файл `src/ups/ups_models.ini` содержит описания различных моделей UPS:

- OID-поля
- типы параметров
- наборы разрешённых значений
- правила интерпретации статусов

Формат позволяет расширять поддержку новых устройств без изменения исходного кода.
